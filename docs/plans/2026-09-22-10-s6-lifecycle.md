# S6: Linux lifecycle, auto-connect и диагностика

**Дата:** 2026-09-22. **Цель:** UC16–21 и UC25 из [Ubuntu completion spec](2026-09-22-02-ubuntu-completion-spec.md). После закрытия или `kill -9` UI daemon-owned WG/OpenVPN/Xray TUN и static routes остаются активными; новый UI читает фактическое состояние и может им управлять. После краша daemon systemd поднимает его, он убирает leftovers и восстанавливает только явно включённые always-on profiles. Обычные tests используют fake adapters; netlink/systemd сценарии выполняются только через `e2e/linux/run.sh`.

## Проверенная отправная точка и границы

- **inspected:** `src-tauri/src/lifecycle.rs::handle_window_event` и `handle_run_event` вызывают `cleanup_all` перед каждым штатным выходом. `cleanup_all` снимает route owners и локальные tunnels. На Linux это прямо противоречит daemon ownership; `src-tauri/src/commands/recovery.rs::cleanup_recovery` тоже использует `cleanup_all`, поэтому их нельзя просто удалить вместе.
- **inspected:** `crates/daemon/src/core.rs::open_with_wireguard_full` уже делает startup teardown по journal, `main.rs` вызывает `shutdown` при SIGTERM. `owned.list`, `subscribe`, `owned.changed` и `resync` UID-scoped в `server.rs`; `recovery.cleanup` очищает только вызывающий uid. `src-tauri/src/daemon_client.rs` открывает новый Unix socket на каждый RPC и не держит подписку. `get_tunnel_statuses` читает daemon только для WG; `App.tsx` и `ProfileManager.tsx` опрашивают статусы каждые 2 секунды.
- **inspected:** `Profile.auto_connect` (`crates/core/src/models.rs`, `src/types.ts`) уже хранится, но запуска при login нет. `src-tauri/Cargo.toml` использует `tauri 2.11.5` из `Cargo.lock` без `tray-icon` и autostart plugin; `src/components/Settings.tsx` не содержит lifecycle settings.
- **Зависимости:** законченные S3/S4/S5 Linux daemon paths, включая `openvpn.status`, `xray.status` и полное journal ownership. Пока в checkout OpenVPN остаётся локальным child, а Linux Xray TUN явно отвергается; раннее включение S6 для них создаст ложное обещание пережить UI crash. Xray SOCKS/HTTP по [S5-плану](2026-09-22-08-s5-xray-linux.md) остаётся UI-owned; UC16 формулируется как сохранение **daemon-owned tunnels**. Если UC16 должен включать и локальный SOCKS/HTTP proxy, нужен отдельный unprivileged runtime с независимым от UI lifetime — это самостоятельное расширение scope.

## Контракт поведения

1. **Close/Quit/Disconnect all.** На Linux `CloseRequested` скрывает окно, оставляя tray/UI process; tray `Quit` завершает только UI. Ни одно из этих действий не вызывает `cleanup_all` или `recovery.cleanup`. `Disconnect all` — отдельное явное действие: по `owned.list` текущего UID отключает daemon owners в обратном порядке и локальные UI-owned процессы, затем проверяет пустой список; чужие UID не затрагивает. На Windows сохранить текущую cleanup семантику. При logout/SIGTERM UI выходит без daemon cleanup; system service teardown остаётся в `main.rs` и используется при stop/uninstall.
2. **Reattach.** При каждом запуске UI делает `hello`, открывает один долгоживущий `subscribe` stream, затем читает `owned.list` и backend `*.status`; `owned.list` задаёт набор owners, backend status — health. Подписка запускается **до** snapshot, чтобы не потерять изменение между ними. Каждое `owned.changed` вызывает targeted refresh, `resync` и reconnect — полный snapshot. Ограничить retry с backoff, один listener на процесс, clean cancellation при UI exit. Ошибка daemon показывается как unavailable, прежнее `running` не удерживается бесконечно; при возврате daemon данные обновляются. Active owner не считается recovery issue только из-за повторного запуска UI: в Linux `get_recovery_report` отличает healthy owner от stale/missing resources.
3. **Login auto-connect.** `auto_connect` означает запуск при старте пользовательского UI после `hello`/reattach. Один проход по сохранённому порядку profiles, без повторного connect для уже owned/running; проверка конфликтов и ошибок идёт тем же `connect_profile` path, без bypass polkit. Ошибки одного профиля не блокируют следующие совместимые, а остаются в status/diagnostics. Static routes применяются заново только если owner отсутствует. OpenVPN, которому нужен интерактивный credential, ждёт UI prompt после login; отсутствие секрета не приводит к silent retry loop. Повторный запуск UI в той же session не дублирует owners.
4. **Always-on до login.** Это отдельный opt-in от `auto_connect`. UI передаёт daemon проверенный snapshot профиля и managed config/assets **по содержимому**, а daemon атомарно хранит versioned root-owned `0600` snapshot под `/var/lib/network-orchestrator/profiles/<uid>/`; не читает user home и не принимает произвольные paths. RPC `always_on.set/list/remove` требует `SO_PEERCRED`, per-UID ownership и polkit authorization, размеры и типы ограничены. При boot/restart daemon после journal cleanup запускает только эти snapshots в стабильном порядке, проверяя конфликты; `Disconnect all` также выключает их автоподъём до явного повторного включения, иначе daemon restart немедленно вернёт отключённое. При редактировании/удалении профиля UI явно обновляет или удаляет snapshot атомарно. OpenVPN profiles с credential без безопасно сохранённого opt-in секрета не допускаются в always-on; passphrase/секрет не пишутся в journal, responses и logs. Доступность pre-login DNS, systemd-resolved и polkit проверить E2E.
5. **Network changes и resume.** Daemon наблюдает netlink LINK/ADDR/ROUTE для активных physical uplinks и `org.freedesktop.login1.Manager.PrepareForSleep` для resume; debounce, сериализация по owner. Для WG проверить link/handshake и заново согласовать маршрут/DNS с текущим uplink; для OpenVPN/Xray использовать процессное состояние/management и их reconnect, затем сверить rules/routes/DNS. Не создавать второй full tunnel и не «лечить» чужой route. Если повторная установка невозможна, пометить owner `failed`/`stale` и снять принадлежащий ему неработающий default route/rule/DNS, чтобы не оставить мёртвый выход; послать `owned.changed`. Простая смена Wi-Fi не должна сбрасывать working tunnel из-за единичного netlink event.
6. **Diagnostics/recovery.** `diagnose_profile` получает WG `wg show`, OpenVPN management state/bytecount, Xray process + listener, `resolvectl status <if>` и проверку owned link/rules/routes через daemon status/snapshot; redacted bounded enum/summary вместо raw config, URI, credential, UUID и log lines. `get_recovery_report` на Linux сообщает только stale/failed/missing owned resources, а `cleanup_recovery` предлагает UID-scoped daemon cleanup с явным подтверждением в UI; normal active tunnel не считается мусором. Cross-user `owned.list`, `subscribe`, `*.status`, `always_on.*`, disconnect и cleanup не раскрывают и не изменяют чужих owners.

## Критические условия и API

- **Текущий `cleanup_all` — blocker до первого инкремента.** Если оставить его на Linux close/quit, UC16 и UC20 невозможны. Если убрать его без замены `cleanup_recovery`, пропадёт явная очистка stale resources. Нужны разные semantics для exit и user-requested cleanup.
- **S4/S5 daemon runtime — prerequisite.** Пока OpenVPN локален, а Xray TUN отсутствует, ни reattach, ни daemon crash recovery для этих backends подтвердить нельзя. Always-on требует безопасных immutable snapshots и явного решения для OpenVPN secrets; `auto_connect` сам по себе не означает разрешение хранить credential под root.
- **Tauri 2 API, проверено по официальным docs:** tray включается feature `tray-icon`, строится `TrayIconBuilder`/`Menu` в Rust setup; на Linux `TrayIconEvent` mouse events не испускаются, поэтому открытие окна должно быть пунктом menu, не обработчиком left click. [System Tray](https://v2.tauri.app/learn/system-tray/). `tauri-plugin-autostart` поддерживает Linux, предоставляет Rust `ManagerExt::autolaunch().enable()/disable()/is_enabled()` или JS API с permissions `autostart:allow-*`; он запускает UI при login, а pre-login обеспечивает только system daemon. [Autostart](https://v2.tauri.app/plugin/autostart/). На Ubuntu GNOME/Wayland наличие видимого tray зависит от shell integration и проверяется на целевой VM; меню должно оставаться доступным через окно, если indicator недоступен. [Tauri single-instance](https://v2.tauri.app/plugin/single-instance/) подходит для повторного launch.
