# S4 — OpenVPN на Linux

**Дата:** 2026-09-22 · **Основание:** [Ubuntu completion spec](2026-09-22-02-ubuntu-completion-spec.md) §3 D1–D3, D5–D6; §5.C; §6 UC06–08; §7 S4. **Статус:** split/full и DNS проверены в Docker (18 OpenVPN checks); credentials и desktop acceptance остаются.

## Цель и границы

Импортированный `.ovpn` с inline или managed cert/key assets подключается на Ubuntu через root daemon. Daemon владеет процессом OpenVPN, детерминированным `ovpn-*` TUN, маршрутами, policy rules и per-link DNS. UI показывает `CONNECTING`/`CONNECTED`/`RECONNECTING`, bytecount и безопасную ошибку авторизации; закрытие UI не разрывает туннель. `disconnect`, неудачный connect, остановка и restart daemon'а убирают только свои ресурсы. Приёмка: UC06–08 на Ubuntu 26.04 и в двухконтейнерном Linux E2E, затем полный quality gate из `AGENTS.md`.

S4 не включает auto-connect/always-on, смену сети и tray (S6), упаковку `.deb` (S7), Windows-паритет и произвольные OpenVPN plugins/scripts. Предположение: S3 к началу реализации уже предоставляет рабочие операции для table/mark/rules и per-link DNS; если нет, S4 сначала закрывает эту конкретную зависимость, без второго route/DNS backend.

## Состояние и проверенные ограничения

- **inspected:** `crates/core/src/daemon_protocol.rs` уже содержит `wireguard.*`, но нет `openvpn.*`; `OwnedResource` в текущем checkout ещё содержит только `Route`. S3-файл плана описывает нужное расширение журнала. `src-tauri/src/commands/tunnels.rs` и `crates/core/src/vpn.rs` пока запускают OpenVPN в процессе UI; pushed routes читаются из локального log. `crates/core/src/config_vault.rs::stage_openvpn` переносит referenced assets и предупреждает о script directives, но сохраняет сами директивы. Для root-запуска нужна отдельная строгая проверка **после** импорта.
- **inspected:** `e2e/linux/run.sh` уже поднимает отдельные `client` и `server` на private Docker network, но `server` пока служит HTTP, а `scenarios.sh` проверяет S1. `Dockerfile` уже устанавливает `openvpn`.
- **official packages:** Ubuntu 26.04 публикует OpenVPN **2.7.0**, Debian 13 — **2.6.14**, Arch — **2.7.7**. План должен работать на 2.6 и 2.7; проверить `openvpn --version` в E2E перед запуском. [Ubuntu package](https://packages.ubuntu.com/resolute/openvpn), [Debian package](https://packages.debian.org/trixie/openvpn), [Arch package](https://archlinux.org/packages/extra/x86_64/openvpn/).
- **official manuals:** `--mark` маркирует зашифрованный transport на Linux; `--route-nopull` отбрасывает pushed routes **и DHCP/DNS options**, но оставляет server-assigned TUN address; `--route-noexec` запрещает OpenVPN самому менять routes. Unix management socket по умолчанию доступен другим локальным процессам, поэтому нужен закрытый каталог и `--management-client-user root`. В 2.7 есть `--dns-updown disable`, которого нет в 2.6; использовать `--ignore-unknown-option dns-updown --dns-updown disable` и подтвердить на обеих версиях. [OpenVPN 2.6 manual](https://openvpn.net/community-docs/community-articles/openvpn-2-6-manual.html), [OpenVPN 2.7 manual](https://openvpn.net/community-docs/community-articles/openvpn-2-7-manual.html).

## Инкременты TDD (каждый: RED → GREEN → проверка)

1. **Контракт и безопасный план запуска.** В `crates/core/src/daemon_protocol.rs` добавить `openvpn.connect/status/disconnect` с typed params/results, `hello.capabilities` и redacted `Debug`: `profileId`, bytes конфигурации и конечный набор managed assets, явные `profile.routes`, credentials только для текущего connect; uid берётся исключительно из `SO_PEERCRED`. `crates/daemon/src/openvpn.rs` разбирает `.ovpn` fail-closed: разрешает лишь проверенные client options и inline cert/key blocks; запрещает вложенный `config`, `plugin`, все script hooks (`up/down/route-up/route-pre-down/ipchange/tls-verify/tls-crypt-v2-verify/auth-user-pass-verify/client-connect/client-disconnect/learn-address/dns-updown`), внешние `log/status/writepid/tmp-dir/cd/chroot/dev-node/management/daemon/user/group` и прочие пути/команды, которыми можно заставить root писать или запускать код. Неизвестные directives отклоняются без значений в ошибке; игнорируемые безопасные настройки дают enum warning. Для `ca/cert/key/tls-auth/tls-crypt/pkcs12` daemon принимает только содержимое assets из vault, записывает их в закрытый `/run/network-orchestrator/<uid>/<owner>/` (0700/0600), переписывает пути на свои; client-supplied абсолютные пути не открывает. Тесты: malicious directives, quoted/inline syntax, traversal/symlink, oversized config/assets и redaction. → **verify:** `cargo test -p network-orchestrator-daemon openvpn` без сетевых мутаций.
2. **Daemon process ownership.** В `crates/daemon/src/openvpn.rs`, `core.rs`, `journal.rs`, `server.rs`, `validate.rs` и `crates/core/src/daemon_protocol.rs`: до spawn проверить root-owned, user-nonwritable `/usr/sbin/openvpn` или `/usr/bin/openvpn`; не использовать пользовательский backend path. Имя `ovpn-<hash(uid,profileId)>` ≤15 байт; чужой TUN с тем же именем — `conflict`. Зафиксировать owner и план cleanup **до** spawn, стартовать child в cgroup service без shell, с `--config <staged>` и **после него** принудительными `--dev <name> --dev-type tun --route-nopull --route-noexec --script-security 1 --ignore-unknown-option dns-updown --dns-updown disable --management <socket> unix --management-client-user root --auth-nocache --verb 3`; `--mark M` добавлять для full tunnel. Не доверять порядку опций в исходном `.ovpn`. Journal хранит только owner, имя link, routes/rules/DNS, таблицу/mark и process marker; не конфиг, ключи, credentials и не произвольный PID для kill. `disconnect` завершает только свой child через сохранённый handle, ждёт exit, снимает DNS/rules/routes и удаляет `/run` assets. После краша systemd убирает процессы unit cgroup, daemon затем чистит журнал; незавершённый cleanup остаётся `stale`. Тесты с fake runner/журналом: отказ до spawn, timeout, SIGTERM, restart, чужой owner и частичный rollback. → **verify:** daemon unit tests и `crates/daemon/tests/real_socket.rs`.
3. **Credentials и management.** UI (`src/components/ProfileFormModal.tsx`, `src/types.ts`, `src-tauri/src/commands/tunnels.rs`) спрашивает username/password при `auth-user-pass` без файла и passphrase ключа при необходимости; неверный пароль даёт безопасную ошибку. Существующие `auth-user-pass <file>` или inline credentials разбираются из managed vault; privileged config получает `auth-user-pass` **без аргумента** (аналогично `askpass`), чтобы запрос пришёл в management. Opt-in «запомнить» сохраняет секрет отдельно через Secret Service (если выбран и доступен), иначе остаётся session-only. Для reauth после `ping-restart` daemon держит секрет только в памяти и отвечает на `--management-query-passwords` через закрытый management socket; не полагается на удалённый после handshake auth-file. Протокол management разбирает `state`, `>STATE`, `>BYTECOUNT`, `>PASSWORD`, `>LOG` с лимитами; `--management-hold` до подключения reader, затем `hold release`. `AUTH_FAILED` прекращает connect с rollback; `RECONNECTING` временно обновляет статус, не дублирует ресурсы. Ни log tail, ни RPC, ни journal не содержат credential/PUSH_REPLY целиком. Тесты: запрос/requery, wrong password, разрыв management, redaction и reattach UI. → **verify:** parser/unit tests + app command tests.
4. **Pushed routes, full tunnel и DNS.** Management `log on all` даёт `PUSH_REPLY`: разобрать bounded `route`, `route-ipv6`, `redirect-gateway def1`, `dhcp-option DNS/DOMAIN` и поддерживаемые 2.7 `dns` options, не исполняя прочие pushed options. Перенести чистую часть `crates/core/src/vpn.rs::parse_openvpn_pushed_reply` в общий parser, сохраняющий DNS и provenance; не использовать unredacted log. Явные `profile.routes` имеют ту же семантику, что у WG; фактические pushed routes появляются после `CONNECTED`. `def1` означает full tunnel (`0.0.0.0/1` + `128.0.0.0/1`) и требует S3 table `T`/mark `M`, проверки занятости второго full owner и проверки `ip route get` для помеченного endpoint и обычного destination. IPv6 покрывать только при pushed `::/0`/эквиваленте и честно показывать отсутствие покрытия. Применять routes/DNS одним owned набором после handshake; при новом `PUSH_REPLY` на reconnect заменять owned набор, не оставляя старый. Per-link DNS через `resolvectl`; если resolved недоступен, status предупреждает `dnsNotApplied`. Тесты: malformed/hostile PUSH_REPLY, split, def1, DNS, reconnect замена, collision и rollback. → **verify:** unit tests + E2E assertions маршрутов, rules и resolved.

## Риски и решения

- **Root config surface:** OpenVPN имеет много file/script/plugin options; `--script-security 1` сам по себе не является sandbox. Fail-closed allowlist и проверка конечного конфигурационного файла до spawn обязательны. [OpenVPN 2.6 manual](https://openvpn.net/community-docs/community-articles/openvpn-2-6-manual.html).
- **DNS visibility:** `--route-nopull` отбрасывает pushed `dhcp-option`, поэтому daemon извлекает их из management `PUSH_REPLY`; если конкретный server не сообщает DNS там, UI показывает отсутствие DNS, а не заявляет защищённый DNS. [OpenVPN 2.7 manual](https://openvpn.net/community-docs/community-articles/openvpn-2-7-manual.html).
- **Reconnect и секреты:** удаление auth-file сразу после handshake конфликтует с reauth; management query и хранение секрета только в памяти daemon до disconnect сохраняют reconnect без plaintext на диске. [OpenVPN management interface](https://openvpn.net/community-docs/management-interface.html).
- **Crash boundary:** systemd обычно убирает процессы unit cgroup при restart, но это подтвердить E2E; journal cleanup не должен убивать PID, который уже принадлежит другому процессу. Полное восстановление активного туннеля после daemon crash — S6.
