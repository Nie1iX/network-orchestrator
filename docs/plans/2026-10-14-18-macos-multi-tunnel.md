# macOS: несколько туннелей одновременно (2026-10-14)

**Статус:** этап A (роли для Xray, OpenVPN, WireGuard) реализован и проверен
юнит-тестами с фейками; живой прогон с несколькими настоящими туннелями на
машине с root ещё не делался. Этап B (NetBird) — ниже, когда будет готов.

## Задача

Запускать Xray, OpenVPN и WireGuard вместе: основной забирает почти весь
трафик, дополнительные — только вручную заданные сети (например, `10.10.0.0/16`
через OpenVPN, другие корпоративные адреса через WireGuard). Любой из трёх
протоколов можно сделать основным. Выбор пользователя: деление **только по
сетям (CIDR)**, **по одному профилю на протокол**.

## Модель

- `Profile.tunnel_role` (`primary` по умолчанию, `secondary`),
  `Profile.tunnel_networks` (сети дополнительного туннеля, отдельно от
  `routes`, куда импорт OpenVPN кладёт маршруты из конфига),
  `Profile.tunnel_dns_domains` (суффиксы для раздельного DNS).
- Протокол: `role` у `xray.connect`/`wireguard.connect`/`openvpn.connect` и
  `dnsDomains` у последних двух; `routes` несёт сети дополнительного туннеля.
  Поля необязательные, Linux их игнорирует.
- `secondary_networks` (core) проверяет список: не пустой, без default route
  (это дело основного), без multicast/loopback, не больше 512, нормализует
  биты хоста.

## Как это работает

- **Один основной.** Helper отклоняет второй основной туннель (`conflict`:
  «уже основной; сделайте один из них дополнительным»). Дополнительные не
  конфликтуют ни с чем, кроме экземпляра того же протокола (по одному на
  протокол).
- **Маршруты.** Основной ставит захват (Xray: восемь префиксов `/1…/8` и две
  половины v6; WireGuard/OpenVPN: половины `/1`, либо `AllowedIPs`/push).
  Дополнительный ставит только свои сети: они длиннее и потому выигрывают у
  захвата основного. Xray-дополнительный — через шлюз `169.254.10.1`,
  WireGuard/OpenVPN — через `-interface utunN`. Если ни одну сеть не удалось
  добавить, подключение откатывается.
- **WireGuard** как дополнительный игнорирует `0.0.0.0/0` из конфига;
  единственному пиру добавляются сети пользователя в `AllowedIPs`, чтобы пакеты
  не отбрасывались. **OpenVPN** как дополнительный игнорирует push-маршруты и
  redirect-gateway, но обход до IP сервера ставит всегда (иначе основной туннель
  захватил бы его собственный трафик).
- **DNS.** Основной заменяет DNS сервиса, как раньше. Дополнительный DNS
  сервиса не трогает: для заданных `dnsDomains` он пишет
  `/etc/resolver/<домен>` с DNS-серверами конфига/push (`resolver.rs`, файлы
  помечены маркером и удаляются только свои; запись в журнале, чистка при
  отключении, выходе и рестарте helper'а). Без доменов DNS не меняется совсем.
- **Журнал** по-прежнему отдельный на каждый протокол (`xray-tun.json`,
  `wireguard.json`, `openvpn.json`).

## Клиент

В карточке подключения (Xray TUN, WireGuard, OpenVPN) переключатель роли
«Основное / Дополнительное»; у дополнительного — список сетей и кнопка
«Изменить сети…» (окно с сетями по одной в строке и необязательными
DNS-доменами; ошибки проверки показываются там же). Смена роли или сетей
перезапускает работающее подключение.

## Ограничения

- По одному активному профилю на протокол.
- Сети дополнительного туннеля, пересекающиеся между двумя туннелями, вторым
  добавляются best-effort (маршрут уже занят — пропускается).
- Деление по доменам для трафика (не DNS) не реализовано, только по сетям.
- Живой E2E с несколькими туннелями — только на машине с root.
