# S1 — привилегированный daemon (Linux)

**Дата:** 2026-09-22 · **Спека:** `2026-09-22-02-ubuntu-completion-spec.md` §7 S1 ·
**Закрывает:** B4, B8, B9, A1–A7 (в объёме S1), E1

**Цель.** Заменить `pkexec linux-helper` системной службой
`network-orchestrator-daemon`:

- работает от root, принимает запросы через unix socket по версионированному
  NDJSON-протоколу;
- клиент идентифицируется через `SO_PEERCRED`, каждое мутирующее действие
  авторизуется через polkit;
- ведёт журнал владения и при старте убирает leftovers.

В S1 через daemon идут маршруты (batch, `via`, поле таблицы) и interface
up/down. В `src-tauri` появляется runtime-абстракция: in-process на
Windows, daemon client на Linux.

WireGuard, OpenVPN и Xray в daemon в S1 не переносятся — это S3–S5. Протокол,
журнал и абстракция оставляют для них точки расширения.

**Стек:** Rust, tokio (`UnixListener`, `peer_cred`), `rtnetlink =0.14.1` +
`netlink-packet-route =0.19.0` (уже в `Cargo.lock` транзитивно через
`net-route`), `zbus 5.19` (уже в `Cargo.lock` через `tauri-plugin-opener`),
`libc` (`SO_PEERPIDFD`), systemd, polkit 127.

## 1. Архитектурные решения

- **R1. Crate.** `git mv crates/linux-helper crates/daemon`: пакет и bin
  `network-orchestrator-daemon`, установленный путь
  `/usr/lib/network-orchestrator/network-orchestrator-daemon` (не `/usr/libexec`: Arch его запрещает, см. `2026-09-22-05-backend-facts.md` §7). `validate_iface_name` переносится
  вместе с тестами; `parse_args`/`ip_route_args`/`run` и pkexec-policy
  удаляются.
- **R2. Протокол** — модуль `crates/core/src/daemon_protocol.rs`,
  платформо-нейтральный, с golden-тестами. Отдельный crate не заводим.
- **R3. Мутации через `rtnetlink`, а не `ip`.**
  - Batch идёт через один socket; ошибки типизированы по errno.
  - Меньше исполняемых файлов запускается от root.
  - `rule()` и `table_id` понадобятся в S3.
  - Маршрут добавляется эксклюзивно (`NLM_F_EXCL`) с собственным `RTPROT`
    = 79, поэтому чужой маршрут не перезаписывается и не удаляется.
  - rtnetlink асинхронный, поэтому мутации идут через actor-поток с
    `current_thread` runtime (не `spawn_blocking` + вложенный `block_on`).
- **R4. Polkit.** Прямой D-Bus `CheckAuthorization` через `zbus`.
  - Subject — `unix-process` с `pidfd` (`SO_PEERPIDFD`); fallback на
    `pid` + `start-time` + `uid`.
  - `polkit.dismissed` отличает «отклонено» от «закрыто».
- **R5. Авторизация:**

  | Метод | polkit action |
  |---|---|
  | `hello`, `owned.list`, `subscribe` | — (только uid, видны свои записи) |
  | `routes.apply`, `link.set_state` | `com.netmanager.app.system-network` (`auth_admin_keep`) |
  | `routes.remove`, `recovery.cleanup` | `com.netmanager.app.connect-profile` (`allow_active=yes`) |

- **R6. Владение.**
  - Ключ — `(uid, owner)`; чужой owner даёт `notFound`.
  - Таблицу выбирает только daemon: `table` от клиента → `invalidParams`
    (иначе можно писать в `local`).
- **R7. Журнал** `/var/lib/network-orchestrator/state.json`.
  - Запись: 0600, temp + `sync_all` + rename + fsync каталога.
  - Write-ahead: сначала запись `applying`, потом netlink.
  - При старте и SIGTERM выполняется teardown всего, что есть в журнале;
    неудачи остаются как `stale`.
  - Ресурсы — упорядоченный список с тегом `kind`, точка расширения для
    link/rule/dns/process.
- **R8.** Семантика UI в S1 не меняется. `cleanup_all` при закрытии UI
  снимает маршруты — теперь через daemon. «Туннели переживают UI» — S6.
  `TunnelManager` в S1 остаётся in-process.
- **R9. Транспорт.**
  - NDJSON, `MAX_FRAME_BYTES = 1 MiB`, `MAX_ROUTES_PER_REQUEST = 8192`,
    owner — 1..=128 байт без control-символов.
  - `hello` должен прийти за 5 с; не больше 64 соединений.
  - Socket 0666 в `RuntimeDirectory` 0755; безопасность обеспечивает polkit.
- **R10.** `PROTOCOL_VERSION = 1`, точное совпадение в `hello`. Неизвестный
  метод → `unsupportedMethod`, соединение не рвётся. Список поддерживаемого —
  в `hello.capabilities`.

## 2. Протокол v1

Envelope парсится в два этапа: `RequestFrame { id: u64, method: String,
params: Value }`, затем dispatch по `method`.

```json
{"id":1,"method":"hello","params":{"protocol":1,"client":"net-manager-app/0.1.1"}}
{"id":1,"ok":true,"result":{"protocol":1,"daemonVersion":"0.1.1","uid":1000,
  "capabilities":["routes.apply","routes.remove","link.set_state","owned.list","recovery.cleanup","subscribe"]}}
{"id":1,"ok":false,"error":{"code":"protocolMismatch","message":"daemon speaks protocol 1, client 2"}}

{"id":2,"method":"routes.apply","params":{"owner":"static-office","routes":[
  {"destination":"203.0.113.0/24","interfaceIndex":2,"gateway":"192.168.1.1","metric":5},
  {"destination":"2001:db8::/32","interfaceIndex":2,"metric":5}]}}
{"id":2,"ok":true,"result":{"applied":2}}
{"id":2,"ok":false,"error":{"code":"authorizationDismissed","message":"authorization dialog was dismissed; nothing was applied"}}

{"id":3,"method":"routes.remove","params":{"owner":"static-office"}}
{"id":3,"ok":true,"result":{"removed":2}}

{"id":4,"method":"link.set_state","params":{"name":"enp0s3","up":false}}
{"id":4,"ok":true,"result":null}

{"id":5,"method":"owned.list"}
{"id":5,"ok":true,"result":{"owners":[{"owner":"static-office","state":"applied","resources":[
  {"kind":"route","destination":"203.0.113.0/24","interfaceIndex":2,"gateway":"192.168.1.1","metric":5}]}]}}

{"id":6,"method":"recovery.cleanup"}
{"id":6,"ok":true,"result":{"removedOwners":["static-office"],"failed":[]}}

{"id":7,"method":"subscribe"}
{"id":7,"ok":true,"result":null}
{"event":"owned.changed","data":{"owner":"static-office"}}
{"event":"resync"}
```

`ErrorCode`: `handshakeRequired`, `protocolMismatch`, `unsupportedMethod`,
`invalidParams`, `frameTooLarge`, `busy`, `notAuthorized`,
`authorizationDismissed`, `conflict`, `notFound`, `unavailable`, `internal`.

## 7. Риски

1. `runtime`-mutex держится, пока открыто окно polkit, и опрос статусов
   замирает (исправление — S3).
2. `EXCL` вместо `replace` меняет поведение: маршрут, идентичный уже
   существующему, даёт `conflict`. Авто-gateway меняет Windows static
   routes (фикс B9; на Windows не проверен).
3. Рестарт daemon'а при открытом UI: статус static-routes в UI расходится с
   реальностью (исправление — S6).
4. `rtnetlink 0.14` устарел и запинен через `net-route`.
5. Без polkit agent `auth_admin*` отклоняется — текст ошибки должен это
   объяснять.
6. До S3–S5 через daemon работают только static routes и interface up/down.
7. Windows CI собирает daemon-crate: нужны cfg-гейты на уровне модулей.
