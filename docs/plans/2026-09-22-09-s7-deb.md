# S7: Ubuntu/Debian `.deb` bundle

`scripts/build-linux-deb.sh` builds the release daemon, then uses Tauri's
`--bundles deb --no-sign` options to build the desktop app and package both
binaries. It does not install the package or mutate host network state. The
resulting local artifact is under `target/release/bundle/deb/`; AppImage is not
built by this script. Release updater artifacts require a signing key and a
separate signed build.

The global `productName` is `Network Orchestrator`, producing the Debian
package name `network-orchestrator`; the previous name would collide with
Ubuntu/Debian's `network-manager` package. `bundle.targets` defaults to only
`deb`, so generic Linux builds cannot produce AppImage. Windows NSIS builds
must pass `--bundles nsis` explicitly, as the current README command does.

The Tauri 2 `bundle.linux.deb.files` mapping installs the daemon at
`/usr/lib/network-orchestrator/network-orchestrator-daemon`, matching the
systemd unit, and installs the unit and polkit policy from `packaging/linux`.
The package depends on systemd, polkitd, and iproute2. It recommends
systemd-resolved, wireguard-tools, and OpenVPN because not every app feature
needs those optional backends.

On `configure`, `postinst` reloads systemd, enables the daemon, and starts it
when systemd is running. The same action on `abort-upgrade`, `abort-remove`, or
`abort-deconfigure` restores service after a failed package operation. On
`remove` or `upgrade`, `prerm` stops the daemon before its binary or unit is
replaced. The daemon handles SIGTERM by tearing down owned routes, links, DNS,
and tunnels; a failed stop or failed unit state aborts package removal. The
unit allows 30 seconds for teardown. `postrm` reloads systemd after removal.
State under `/var/lib/network-orchestrator` remains after `remove` for recovery
if teardown leaves stale resources. Explicit `purge` deletes that state.

Verification: `sh -n` for scripts, Tauri config schema validation during
bundle build, and `dpkg-deb -c`/`dpkg-deb -I` inspection of the finished
package. In a disposable Ubuntu 26.04.1 Docker container, `apt install` fetched
the GTK/WebKit dependencies, enabled and started the daemon, and exposed its
Unix socket. A route applied through the daemon was removed by `apt remove`:
the journal reported one owner removed and zero stale. `apt purge` then removed
the state directory. Unit, binary, policy, app, socket, and enable symlink were
absent after purge. Package installation, GUI behavior, and active-tunnel
teardown still need acceptance on an Ubuntu VM; no package was installed on the
host.

A separate Xvfb smoke in the same disposable Ubuntu version installed the `.deb`
with GUI runtime dependencies, started `/usr/bin/net-manager-app` as uid 1001
with temporary XDG directories and a user D-Bus session, and found its X11
window. Screenshots showed a rendered Home view and the read-only Network view
with `eth0` and `lo` data. The app process stayed alive; its log contained only
headless AT-SPI and EGL/DRI3 warnings. `apt remove` and `apt purge` passed in
that container, and all package files and state were absent afterward.
